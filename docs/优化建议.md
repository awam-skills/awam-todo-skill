## 一、数据层（决定了后面一切能算什么）

### 7 + 8. 进展记录层 + 派生指标（**最高优先级，其他多条都依赖它**）

- **现状缺口**：`storage/YYYY-MM-DD.md` 只保存任务的**当前状态**与创建/更新时间，没有"某天做了多少"的记录。
  因此连续天数、完成率、预计完成日、分钟投入、周报环比都无从计算——目前 `_projected_finish()` 恒定返回
  `None`，界面显示「暂无推算」。这是刻意的不编造，不是缺陷。
- **目标**：让一条待办可以有**多次**推进记录，进而算出真实的进度与速度。
- **方案要点**
  1. 任务块内追加记录行，例如：
     ```
     进展: 2026-10-06 30分钟 60个 补记:false
     进展: 2026-10-04 25分钟 40个 补记:true
     ```
     格式建议 `进展: <日期> [<分钟>分钟] [<数量><单位>] [补记:true]`；分钟与数量都选填。
  2. 新增命令：`log <id> [--amount N] [--minutes N] [--date YYYY-MM-DD] [--makeup]`，
     以及 `unlog <id> <记录序号>` 删除单条（对应"最近 N 条可删记录"）。
  3. 补记窗口限制为最近 6 天，补记带「补」标记，但**按真实日期**参与连续天数与速度推算。
  4. 派生指标一律由记录实时算出，不落库：完成率、连续天数、近 7 天均速、预计完成日。
  5. **样本不足仍显示「暂无推算」**（`PROJECTION_MIN_SAMPLES = 3`），不编数字。
  6. 一天可记多次；未填分钟的记录在图表里不硬凑（见下文 18/19 的图表口径）。
- **优先级**：P0（阻塞 18、19，也是把 1「不推算」原则真正兑现的前提）
- **依赖**：需要同步改 `_parse_block` / `_write_block` / `_task_view` / `build_index`，
  并引入 `SCHEMA_VERSION = 3` + `migrate` 迁移规则（v2 → v3 仅新增字段，向后兼容）。

### 10. 导出 / 导入 JSON（含覆盖确认）

- **现状缺口**：数据只躺在 `storage/*.md` 和 `index.json` 里，没有整体导出通道，换机器/备份只能手工拷目录。
- **目标**：一条命令导出全部数据为单文件 JSON；导入时**明确提示将覆盖现有数据**并要求确认。
- **方案要点**
  1. `export [--out 路径] [--since YYYY-MM]`：导出 `{schema_version, generated, files:[{date, archived, tasks}],
     archives:[{month, tasks}], env:{path_style, defaults}}`。
  2. `import <文件> [--dry-run] [--force]`：默认先打印将被覆盖的文件数与任务数，
     `--force` 才真正覆盖；导入前自动把现有 `storage/` 备份为 `storage.bak-<时间戳>/`。
  3. 导入时按 `schema_version` 走迁移链，遇到高于当前版本的字段**报错而不是静默丢弃**。
- **优先级**：P1
- **依赖**：建议在 7/8 之后做，否则导出格式还要再改一次。

## 二、交互与提示

### 17. 行为触发的温和提示（而不是定时弹窗）

- **现状缺口**：目前没有任何"该整理/该备份了"的提醒；做定时弹窗很容易变成打扰。
- **目标**：用**行为阈值**触发一次性、可直接处置的提示条。
- **方案要点**
  1. 阈值建议做成常量并允许 `env.json` 覆盖：
     `NUDGE_LOG_COUNT = 20`（累计记录数）、`NUDGE_DIRTY_PATCHES = 15`（未落盘更改数）、
     `NUDGE_STORAGE_FILES = 30`（未归档日文件数）。
  2. 触发时页面顶部出现**温和横幅**（紫色，不是红色告警），右侧直接给按钮：
     「导出备份」「立即保存」「归档旧记录」——提示必须自带出口。
  3. 关闭后记入 `localStorage`，同一阈值不重复打扰；阈值跨过下一个量级才再提示。
  4. CLI 侧在 `list` / `index` 输出末尾附一行同样的提示（纯文本，不打断退出码）。
- **优先级**：P2
- **依赖**：导出功能（10）。

### 24. 示例数据与"清空示例"

- **现状缺口**：`storage/` 里是真实待办，没有可一键还原的演示数据；新装或换机器后界面是空的，
  无法直观看到逾期/停滞/预案等状态长什么样。
- **目标**：提供一份覆盖全部边界状态的示例数据集，且能一键清除、不影响真实数据。
- **方案要点**
  1. 示例数据放在 `samples/`（不进 `storage/`），命令 `demo load` 复制进 `storage/`，
     `demo clear` 只删除带 `示例` 标签的内容。
  2. 示例需覆盖：逾期 3 天、连续漏打（停滞）、补记记录、障碍+对策、依赖阻塞、子任务、已完成归档。
  3. **绝不在用户已有数据时自动灌入示例**：`demo load` 前若 `storage/` 非空必须二次确认。
- **优先级**：P3
- **依赖**：7（要演示补记/连续天数必须先有记录层）。

## 三、周期复盘

### 18. 周报（周一→周日汇总 + 同口径环比）

- **现状缺口**：只有 `week.created / week.done` 两个计数，没有按周查看历史、没有环比、没有产出文本。
- **目标**：一条命令产出本周投入全景，并能回看任意历史周。
- **方案要点**
  1. 口径固定：周一 00:00 至周日 23:59（已落 `WEEK_START_ISO`，复用即可）。
  2. `report [--week YYYY-Wxx | --date YYYY-MM-DD]`：汇总投入量、打卡天数、分钟数、完成条数，
     并与**上周同口径**对比（同指标、同单位；上周无数据则显示「暂无环比」，不显示 0%）。
  3. 历史周可翻阅：索引里保留每周一行摘要，避免每次全量重算。
- **优先级**：P1
- **依赖**：7（没有记录就没有"投入量/分钟数"）。

### 19. 四栏复盘（保持 / 问题 / 尝试 / 下周预案）

- **现状缺口**：复盘目前只存在于对话里，没有结构化沉淀，下周无法回看。
- **目标**：每周四栏自由文本随周报一起持久化，并纳入一键生成的周报文本。
- **方案要点**
  1. 存储位置建议：`storage/weekly/YYYY-Wxx.md`（不参与日常索引，避免污染日文件）。
     四栏字段：`保持` / `问题` / `尝试` / `下周预案`。
  2. `report --note 保持=xxx 问题=yyy` 增量写入；网页端在周报页直接编辑并即时保存。
  3. `report --text` 一键生成纯文本周报：本周数字 + 环比 + 四栏内容，可直接粘贴到日报/群里。
- **优先级**：P2
- **依赖**：18。

## 四、体验细节

### 22. 完成时的彩带动效

- **现状缺口**：把任务标记为「结束」只有一行 toast，没有完成感。
- **目标**：完成时给一次轻量正向反馈，但**不打扰、不阻塞、可关闭**。
- **方案要点**
  1. 纯内联实现：用 `document.createElement` 生成 20~30 个 `div`，CSS `transform` 动画，1.2 秒后移除。
  2. 触发条件：状态从非「结束」变为「结束」，且当次操作 ≤ 3 条（批量完成不放彩带）。
  3. 尊重 `prefers-reduced-motion: reduce`；网页端提供开关存 `localStorage`。
- **优先级**：P4（纯体验，随时可做）

## 五、暂不建议做

- **把「总量/单位/截止」的量化目标模型硬塞进 todo 主模型**：todo 是一次性完成的状态机
  （待开始/进行中/结束），量化目标是累积型计数器，两者语义冲突。若要支持，应作为**可选计量字段**
  （`目标总量/当前/单位`）叠加，或另开视图，而不是改 todo 的定义。
- **改成纯 localStorage 的单文件方案**：当前"文件即真相 + CLI/网页同源 + revision 合并 + patch 队列"
  的架构更严谨，不要为了"单文件"倒退。

## 六、已落地（v0.7.0）

### 23. 分诊入口 triage（纯规则、不依赖大模型）

- **现状缺口**：此前"一句话是该新增 / 更新 / 改状态 / 删除"只能靠会话里的大模型判断，无法脱离 LLM 独立使用。
- **已落地**：scripts/todo.py triage --text "..." —— 只读、纯规则：判定顺序 删除 > 改状态 > 更新 > 新增；
  疑问句/无动作句回落 unknown + need_confirm；「需要/要/必须…」承诺句强制回落 add；按 T-ID 或文本相似度
  锁定真实任务（优先未结束），锁定不了给 candidates / fallback_action=add；规则抽取 截止/重要/紧急/备注:/标签:/路径。
  JSON 契约：action / confidence / need_confirm / reasons / text（原句原文，不做筛选）/ target / candidates /
  status / fields / suggested_tags / fallback_action；need_confirm 或破坏性删除时退出码 3。
- **用法**：AI 会话里直接对用户原话跑 triage，再按需确认后执行底层命令（add / done、start / add --update-id / delete）。

### 24. 捕获服务 capture（全局快捷键 → 剪贴板 → 分诊 → 系统弹框）

- **现状缺口**：想随手把剪贴板里的一段话变成待办，没有快捷入口。
- **已落地**：scripts/capture.py（纯标准库）+ 融合进 web/server.py 进程：
  - **不做规则筛选**：剪贴板原文就是任务内容，原样交给分诊入口；
  - Win32 全局快捷键（默认 Ctrl+Alt+T，RegisterHotKey + 消息循环线程）+ CF_UNICODETEXT 读剪贴板；
  - 需要确认 / 填写一律系统弹框（tkinter）：判定展示、目标候选下拉、截止/标签/备注/重要/紧急、
    新状态下拉；删除必确认（可关）；守卫拦截时再弹「是否强制」；
  - 配置在 env.json 的 capture 段（enabled / hotkey / confirm_delete / toast / triage_types），
    网页 UI 新增设置页管理，含「试用分诊」只读演示；API：GET|PUT /api/settings、POST /api/capture/triage。
- **边界**：仅 Windows（快捷键与剪贴板为 Win32 能力），无 GUI 环境优雅降级为不启动监听；快捷键被占用时报错提示改键。
